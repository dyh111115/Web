# Day 6 详细知识点

## 1. 系统调用如何表示成功和失败

Linux 系统调用通常通过返回值表示结果。

常见返回约定：

| 系统调用 | 成功 | 失败 |
|---|---|---|
| `open()` | 返回非负 fd | 返回 `-1` |
| `read()` | 返回读取字节数，可能为 `0` | 返回 `-1` |
| `write()` | 返回写入字节数 | 返回 `-1` |
| `close()` | 返回 `0` | 返回 `-1` |
| `socket()` | 返回非负 fd | 返回 `-1` |
| `bind()` | 返回 `0` | 返回 `-1` |
| `listen()` | 返回 `0` | 返回 `-1` |
| `accept()` | 返回非负 connfd | 返回 `-1` |
| `epoll_create()` | 返回非负 epollfd | 返回 `-1` |

但不同接口的失败形式可能不同：

| 函数 | 失败形式 |
|---|---|
| `malloc()` | 返回 `NULL` |
| `pthread_create()` | 返回错误码，成功返回 `0` |
| C++ 标准库函数 | 常通过异常报告失败 |

核心原则：

> 先检查返回值，确认调用失败后再读取 `errno`。

## 2. `errno`

C++ 中建议包含：

```cpp
#include <cerrno>
```

示例：

```cpp
int fd = open("/not/exist/file.txt", O_RDONLY);

if (fd == -1)
{
    std::cerr << "errno = " << errno << '\n';
}
```

可能输出：

```text
errno = 2
```

`2` 通常对应：

```text
ENOENT
No such file or directory
```

应使用错误码宏：

```cpp
if (errno == ENOENT)
{
    std::cerr << "文件不存在\n";
}
```

不要写死数字，因为不同系统中数字可能不同。

### 规则 1：只有失败后才有意义

```cpp
int fd = open(path, O_RDONLY);

if (fd == -1)
{
    // 此时 errno 才有意义
}
```

### 规则 2：不能用 `errno == 0` 判断成功

错误写法：

```cpp
if (errno == 0)
{
    std::cout << "success\n";
}
```

正确写法：

```cpp
if (fd != -1)
{
    std::cout << "success\n";
}
```

成功调用不保证把 `errno` 清零。

### 规则 3：后续调用可能覆盖 `errno`

如果还要使用原错误码，应先保存：

```cpp
if (fd == -1)
{
    int error_code = errno;

    std::cerr << "errno=" << error_code << '\n';
}
```

### 多线程中的 `errno`

在 POSIX 多线程程序中，`errno` 通常是线程局部的：

```text
线程 A 的 errno
和线程 B 的 errno
互不影响
```

但同一线程内，后续调用仍可能覆盖之前的 `errno`。

## 3. `perror()`

`perror()` 会读取当前 `errno`，并直接输出错误信息：

```cpp
#include <cstdio>

int fd = open("/not/exist/file.txt", O_RDONLY);

if (fd == -1)
{
    std::perror("open");
}
```

输出：

```text
open: No such file or directory
```

格式：

```text
自定义前缀: 系统错误信息
```

注意：

- `perror()` 应紧跟在失败调用之后；
- 中间如果执行了其他可能修改 `errno` 的函数，原错误可能丢失。

## 4. `strerror()`

`strerror()` 返回错误码对应的字符串：

```cpp
#include <cstring>
#include <cerrno>
#include <iostream>

int fd = open("/not/exist/file.txt", O_RDONLY);

if (fd == -1)
{
    int error_code = errno;

    std::cerr << "open failed: "
              << std::strerror(error_code) << '\n';
}
```

输出：

```text
open failed: No such file or directory
```

对比：

| 函数 | 作用 |
|---|---|
| `perror("open")` | 直接向标准错误输出完整信息 |
| `strerror(errno)` | 返回字符串，由程序自行拼接和输出 |

如果需要在日志中长期保存错误字符串，建议立即复制到 `std::string`，不要长期保存 `strerror()` 返回的指针。

## 5. 完整示例：`error_demo.cpp`

```cpp
#include <fcntl.h>
#include <unistd.h>

#include <cerrno>
#include <cstdio>
#include <cstring>
#include <iostream>

int main()
{
    const char* path = "/tmp/this_file_does_not_exist_12345.txt";

    int fd = open(path, O_RDONLY);

    if (fd == -1)
    {
        int error_code = errno;

        std::cerr << "open failed\n";
        std::cerr << "errno = " << error_code << '\n';
        std::cerr << "strerror: "
                  << std::strerror(error_code) << '\n';

        std::perror("open");

        return 1;
    }

    std::cout << "open success, fd=" << fd << '\n';
    close(fd);

    return 0;
}
```

执行流程：

```text
open() 打开不存在的文件
→ 返回 -1
→ errno 被设置为 ENOENT
→ 保存 errno
→ 使用 strerror() 输出字符串
→ 使用 perror() 输出完整错误
```

## 6. 常见错误码

| 错误码 | 含义 | 常见场景 |
|---|---|---|
| `ENOENT` | 文件或路径不存在 | `open()` |
| `EACCES` | 权限不足 | 读文件、绑定端口 |
| `EEXIST` | 文件已经存在 | `O_CREAT | O_EXCL` |
| `EBADF` | fd 无效 | 使用已关闭的 fd |
| `EINVAL` | 参数无效 | 错误的 flags 或长度 |
| `EMFILE` | 进程 fd 达到上限 | fd 泄漏 |
| `ENFILE` | 系统 fd 达到上限 | 系统资源耗尽 |
| `EINTR` | 调用被信号中断 | `read()`、`accept()` |
| `EAGAIN` | 当前暂时无法完成 | 非阻塞 I/O |
| `EWOULDBLOCK` | 通常与 `EAGAIN` 相同 | 非阻塞 Socket |
| `EADDRINUSE` | 地址或端口被占用 | `bind()` |
| `ECONNREFUSED` | 连接被拒绝 | `connect()` |
| `ECONNRESET` | 连接被对端重置 | `recv()`、`send()` |

后续服务器开发最常关注：

```text
EINTR
EAGAIN
EWOULDBLOCK
ECONNRESET
```

## 7. `EINTR`

`EINTR` 表示：

> 系统调用被信号中断。

例如进程正在等待 `read()`，此时收到某个信号，`read()` 可能返回 `-1`，并将 `errno` 设置为 `EINTR`。

常见处理：

```cpp
ssize_t n;

do
{
    n = read(fd, buffer, sizeof(buffer));
}
while (n == -1 && errno == EINTR);
```

含义：

```text
读取被信号打断
→ 没有读到数据
→ 重新执行 read()
```

不是所有被中断的调用都应该无条件重试。对于已经部分完成的操作，需要结合 API 语义判断，但在基础 Socket 读取中，这种重试模式很常见。

## 8. `EAGAIN` 和 `EWOULDBLOCK`

`EAGAIN` 表示：

> 当前没有数据或资源，稍后可能可以继续。

在非阻塞 Socket 中：

```cpp
ssize_t n = recv(fd, buffer, sizeof(buffer), 0);

if (n == -1)
{
    if (errno == EAGAIN || errno == EWOULDBLOCK)
    {
        // 当前没有更多数据，返回事件循环
    }
    else
    {
        // 真正的错误
    }
}
```

在 Linux 上：

```text
EAGAIN 和 EWOULDBLOCK 通常值相同
```

但代码同时判断两者，更便于理解跨平台语义。

## 9. 完整示例：`retry_demo.cpp`

```cpp
#include <fcntl.h>
#include <unistd.h>

#include <cerrno>
#include <cstdio>
#include <iostream>

int main()
{
    int fd = open("/etc/passwd", O_RDONLY);

    if (fd == -1)
    {
        std::perror("open");
        return 1;
    }

    char buffer[256];
    ssize_t n = -1;

    do
    {
        n = read(fd, buffer, sizeof(buffer));
    }
    while (n == -1 && errno == EINTR);

    if (n == -1)
    {
        std::perror("read");
        close(fd);
        return 1;
    }

    if (n == 0)
    {
        std::cout << "end of file\n";
    }
    else
    {
        std::cout << "read " << n << " bytes\n";
    }

    close(fd);
    return 0;
}
```

正常运行时通常不会触发 `EINTR`，重点是掌握标准错误处理结构。

## 11. 完整示例：`bind_port_demo.cpp`

```cpp
#include <arpa/inet.h>
#include <sys/socket.h>
#include <unistd.h>

#include <cstdio>
#include <iostream>

int main()
{
    int fd = socket(AF_INET, SOCK_STREAM, 0);

    if (fd == -1)
    {
        std::perror("socket");
        return 1;
    }

    sockaddr_in address{};
    address.sin_family = AF_INET;
    address.sin_addr.s_addr = INADDR_ANY;
    address.sin_port = htons(9006);

    if (bind(fd,
             reinterpret_cast<sockaddr*>(&address),
             sizeof(address)) == -1)
    {
        std::perror("bind");
        close(fd);
        return 1;
    }

    std::cout << "bind success on port 9006\n";
    std::cout << "keep the process running...\n";

    sleep(60);

    close(fd);
    return 0;
}
```

这里提前接触几个 Socket 概念：

| 内容 | 含义 |
|---|---|
| `AF_INET` | IPv4 地址族 |
| `SOCK_STREAM` | 流式 Socket，通常对应 TCP |
| `INADDR_ANY` | 监听本机所有 IPv4 地址 |
| `htons(9006)` | 把端口转成网络字节序 |
| `bind()` | 把 Socket 绑定到地址和端口 |

Day 8 会正式学习这些概念。

## 12. 复现端口占用

终端 A：

```bash
./bind_port_demo
```

输出：

```text
bind success on port 9006
keep the process running...
```

终端 B：

```bash
./bind_port_demo
```

输出：

```text
bind: Address already in use
```

对应：

```cpp
errno == EADDRINUSE
```

如果 9006 已经被其他程序占用，第一个程序就会失败，可以换一个端口。

## 13. 错误处理的基本模板

```cpp
int fd = open(path, O_RDONLY);

if (fd == -1)
{
    std::perror("open");
    return 1;
}

ssize_t n;

do
{
    n = read(fd, buffer, sizeof(buffer));
}
while (n == -1 && errno == EINTR);

if (n == -1)
{
    std::perror("read");
    close(fd);
    return 1;
}

close(fd);
```

原则：

```text
1. 检查返回值
2. 失败后立即保存或检查 errno
3. 判断错误是否可恢复
4. 可恢复错误重试或等待
5. 不可恢复错误打印日志
6. 关闭 fd、释放内存、退出
```

## 14. 常见错误

| 错误 | 原因 | 处理 |
|---|---|---|
| `open: No such file or directory` | 路径不存在 | 检查路径 |
| `open: Permission denied` | 权限不足 | 检查文件权限 |
| `bad file descriptor` | fd 已关闭或无效 | 检查 fd 生命周期 |
| `Address already in use` | 端口被占用 | 换端口或关闭占用进程 |
| `Cannot assign requested address` | 绑定地址不属于本机 | 检查 IP |
| `Interrupted system call` | 调用被信号中断 | 判断 `EINTR` 并重试 |
| `Resource temporarily unavailable` | 当前无数据或资源 | 判断 `EAGAIN` |
| 读取内容出现乱码 | 文本缓冲区没有 `'\0'` | 补字符串结束符 |

## 15. 与 TinyWebServer 的对应关系

TinyWebServer 启动服务器时会调用：

```text
socket()
bind()
listen()
epoll_create()
epoll_ctl()
epoll_wait()
accept()
recv()
send()
```

每个调用都可能失败。

例如后续会看到类似逻辑：

```cpp
int connfd = accept(listenfd, ...);

if (connfd == -1)
{
    perror("accept");
}
```

在非阻塞读取中：

```cpp
ssize_t n = recv(connfd, buffer, sizeof(buffer), 0);

if (n == -1)
{
    if (errno == EAGAIN || errno == EWOULDBLOCK)
    {
        // 当前没有数据
    }
    else
    {
        // 错误处理
    }
}
```

Day 11 学习非阻塞 Socket 时，`EAGAIN` 会成为关键知识。
