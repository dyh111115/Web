# Day 4 详细知识点

## 1. 从源码到可执行程序

执行：

```bash
g++ main.cpp user.cpp -o user_app
```

看起来只有一步，实际大致经过四个阶段：

```text
main.cpp、user.cpp
→ 预处理
→ 编译
→ 汇编
→ 链接
→ user_app
```

| 阶段 | 主要工作 | 常见产物 |
|---|---|---|
| 预处理 | 展开 `#include`，处理宏和条件编译 | 预处理后的源码 |
| 编译 | 检查 C++ 语法和类型，生成汇编代码 | 汇编代码 |
| 汇编 | 把汇编代码转换为机器指令 | `main.o`、`user.o` |
| 链接 | 合并目标文件，解析函数和库 | `user_app` |

简化记忆：

```text
编译：把单个 .cpp 变成 .o
链接：把多个 .o 和库变成可执行文件
```

## 2. `.h`、`.cpp`、`.o` 和可执行文件的区别

| 文件 | 作用 |
|---|---|
| `user.h` | 声明类、函数和公共接口 |
| `user.cpp` | 实现 `user.h` 中声明的成员函数 |
| `main.cpp` | 程序入口，调用 `UserManager` |
| `main.o` | `main.cpp` 编译后的目标文件 |
| `user.o` | `user.cpp` 编译后的目标文件 |
| `user_app` | 链接后得到的最终程序 |

一句话理解：

```text
.h  表示“有什么”
.cpp 表示“怎么做”
.o  是单个源文件编译后的半成品
可执行文件是链接后的最终成品
```

## 3. `main.cpp` 和 `user.cpp` 的接口

`main.cpp` 不直接包含 `user.cpp`。双方都包含 `user.h`：

```text
main.cpp
   │ #include "user.h"
   ▼
user.h  ← 公共接口声明
   ▲
   │ #include "user.h"
user.cpp  ← 具体实现
```

`user.h` 完整内容：

```cpp
#ifndef USER_H
#define USER_H

#include <map>
#include <string>

class UserManager
{
public:
    UserManager();

    bool addUser(const std::string& name,
                 const std::string& password);

    bool checkPassword(const std::string& name,
                       const std::string& password) const;

    void printAll() const;

private:
    std::map<std::string, std::string> users_;
};

#endif
```

`public` 部分是外部可以使用的接口：

| 接口 | 作用 | 返回值 |
|---|---|---|
| `UserManager()` | 创建对象并初始化用户 | 无 |
| `addUser(name, password)` | 添加用户 | 成功 `true`，失败 `false` |
| `checkPassword(name, password)` | 检查用户名和密码 | 正确 `true`，否则 `false` |
| `printAll()` | 输出全部用户 | 无 |

`private` 中的 `users_` 不属于外部接口。`main.cpp` 不能直接访问：

```cpp
users.users_; // 错误：private
```

只能通过公共成员函数操作对象：

```cpp
users.addUser("bob", "123456");
```

### 头文件保护

```cpp
#ifndef USER_H
#define USER_H

// 声明

#endif
```

作用：

> 防止同一个头文件在一次编译单元中被重复包含。

如果 `user.h` 被重复包含，可能出现类被重复声明的问题。头文件保护是常规写法。

## 4. 完整实现

### `user.cpp`

```cpp
#include "user.h"

#include <iostream>

UserManager::UserManager()
{
    users_["admin"] = "123456";
    users_["alice"] = "alice123";
}

bool UserManager::addUser(const std::string& name,
                          const std::string& password)
{
    if (name.empty() || password.empty())
    {
        return false;
    }

    if (users_.find(name) != users_.end())
    {
        return false;
    }

    users_[name] = password;
    return true;
}

bool UserManager::checkPassword(const std::string& name,
                                const std::string& password) const
{
    auto it = users_.find(name);

    if (it == users_.end())
    {
        return false;
    }

    return it->second == password;
}

void UserManager::printAll() const
{
    for (const auto& item : users_)
    {
        std::cout << item.first << " -> " << item.second << '\n';
    }
}
```

注意：

- `UserManager::` 表示该函数属于 `UserManager` 类；
- `const` 成员函数不能修改对象的数据成员；
- `addUser()` 检查空字符串和重复用户名；
- `find()` 查询时不会插入新元素；
- `it->first` 是用户名，`it->second` 是密码。

### `main.cpp`

```cpp
#include "user.h"

#include <iostream>
#include <string>

int main()
{
    UserManager users;
    std::string command;

    while (true)
    {
        std::cout << "\n命令(add/check/list/quit): ";
        if (!(std::cin >> command))
        {
            break;
        }

        if (command == "add")
        {
            std::string name;
            std::string password;

            std::cout << "用户名: ";
            std::cin >> name;
            std::cout << "密码: ";
            std::cin >> password;

            if (users.addUser(name, password))
            {
                std::cout << "添加成功\n";
            }
            else
            {
                std::cout << "添加失败：用户已存在或输入为空\n";
            }
        }
        else if (command == "check")
        {
            std::string name;
            std::string password;

            std::cout << "用户名: ";
            std::cin >> name;
            std::cout << "密码: ";
            std::cin >> password;

            if (users.checkPassword(name, password))
            {
                std::cout << "密码正确\n";
            }
            else
            {
                std::cout << "用户不存在或密码错误\n";
            }
        }
        else if (command == "list")
        {
            users.printAll();
        }
        else if (command == "quit")
        {
            break;
        }
        else
        {
            std::cout << "未知命令\n";
        }
    }

    return 0;
}
```

## 5. 一次性编译

```bash
g++ -std=c++17 -Wall -Wextra -pedantic main.cpp user.cpp -o user_app
```

运行：

```bash
./user_app
```

参数含义：

| 参数 | 含义 |
|---|---|
| `g++` | 调用 C++ 编译器 |
| `-std=c++17` | 使用 C++17 标准 |
| `-Wall` | 开启常见警告 |
| `-Wextra` | 开启更多警告 |
| `-pedantic` | 严格遵循标准 |
| `main.cpp user.cpp` | 参与编译和链接的源文件 |
| `-o user_app` | 指定输出文件名 |

这条命令同时完成编译和链接，所以平时最常见。

## 6. 分步编译与链接

### 第一步：只编译

```bash
g++ -std=c++17 -Wall -Wextra -pedantic -c main.cpp -o main.o
g++ -std=c++17 -Wall -Wextra -pedantic -c user.cpp -o user.o
```

`-c` 表示：

> 只编译，不链接。

生成：

```text
main.o
user.o
```

目标文件可以用 `file` 查看：

```bash
file main.o
```

通常显示类似：

```text
main.o: ELF 64-bit LSB relocatable
```

`relocatable` 表示它是可重定位目标文件，还不是可执行程序。

### 第二步：链接

```bash
g++ main.o user.o -o user_app
```

这一步主要完成：

- 合并目标文件；
- 解析函数地址；
- 处理外部符号；
- 链接需要的库；
- 生成最终可执行文件。

### 查看符号

可以使用 `nm` 观察目标文件中的符号：

```bash
nm -C main.o | grep UserManager
nm -C user.o | grep UserManager
```

大致会看到：

```text
main.o 中：U UserManager::addUser(...)
user.o 中：T UserManager::addUser(...)
```

含义：

- `U`：undefined，当前目标文件引用了该符号，但没有定义；
- `T`：text section，目标文件中存在该函数的机器代码定义。

链接器的工作就是让 `U` 找到对应的 `T`。

## 7. 三类常见错误

### 错误 1：头文件找不到

错误示例：

```text
fatal error: user.h: No such file or directory
```

原因：

> 预处理器找不到 `#include "user.h"` 指向的文件。

这是编译阶段错误。

如果头文件位于 `include/`：

```bash
g++ -std=c++17 -Iinclude main.cpp user.cpp -o user_app
```

`-I` 用来增加头文件搜索目录。

### 错误 2：函数未定义

错误示例：

```text
undefined reference to `UserManager::addUser(...)'
```

原因：

> 编译阶段看到了声明，但链接阶段找不到函数实现。

这是链接阶段错误。

错误命令：

```bash
g++ -std=c++17 main.cpp -o user_app
```

修复：

```bash
g++ -std=c++17 main.cpp user.cpp -o user_app
```

### 错误 3：函数重复定义

错误示例：

```text
multiple definition of `UserManager::addUser(...)'
```

常见原因：

- 把函数定义写进了头文件；
- 多个 `.cpp` 都包含了这个头文件；
- 链接时同一个定义出现多份。

正确原则：

```text
头文件放声明
.cpp 放定义
```

## 8. Makefile 基础

Makefile 的核心规则：

```makefile
目标: 依赖
	生成目标的命令
```

示例：

```makefile
user_app: main.o user.o
	$(CXX) $(CXXFLAGS) main.o user.o -o user_app
```

含义：

- 目标：`user_app`
- 依赖：`main.o`、`user.o`
- 命令：把目标文件链接成可执行文件

### 为什么命令前必须是 Tab

Make 通过 Tab 区分规则和命令。

如果写成空格，可能报：

```text
Makefile:5: *** missing separator. Stop.
```

## 9. Day 4 完整 Makefile

```makefile
CXX ?= g++
CXXFLAGS ?= -std=c++17 -Wall -Wextra -pedantic

TARGET := user_app
OBJS := main.o user.o

all: $(TARGET)

$(TARGET): $(OBJS)
	$(CXX) $(CXXFLAGS) $(OBJS) -o $@

main.o: main.cpp user.h
	$(CXX) $(CXXFLAGS) -c main.cpp -o $@

user.o: user.cpp user.h
	$(CXX) $(CXXFLAGS) -c user.cpp -o $@

clean:
	rm -f $(TARGET) $(OBJS)

.PHONY: all clean
```

其中 `	` 在实际 Makefile 中必须替换为真正的 Tab。

### 变量解释

```makefile
CXX ?= g++
```

如果没有从环境传入 `CXX`，就使用 `g++`。

```makefile
CXXFLAGS ?= -std=c++17 -Wall -Wextra -pedantic
```

定义通用编译选项。

```makefile
TARGET := user_app
OBJS := main.o user.o
```

定义最终目标和目标文件列表，避免重复书写。

### 默认目标

```makefile
all: $(TARGET)
```

Makefile 的第一个目标通常是默认目标。

因此执行：

```bash
make
```

等价于构建 `all`，而 `all` 又依赖 `user_app`。

### 链接规则

```makefile
$(TARGET): $(OBJS)
	$(CXX) $(CXXFLAGS) $(OBJS) -o $@
```

`$@` 表示当前目标，因此这里展开为：

```text
user_app
```

### 编译规则

```makefile
main.o: main.cpp user.h
	$(CXX) $(CXXFLAGS) -c main.cpp -o $@
```

`main.o` 同时依赖 `main.cpp` 和 `user.h`。

因此：

- 修改 `main.cpp`：重新生成 `main.o`；
- 修改 `user.h`：也重新生成 `main.o`。

### clean 规则

```makefile
clean:
	rm -f $(TARGET) $(OBJS)
```

执行：

```bash
make clean
```

删除：

```text
user_app
main.o
user.o
```

### `.PHONY`

```makefile
.PHONY: all clean
```

告诉 Make：

> `all` 和 `clean` 是命令目标，不代表真实文件。

即使目录中存在名为 `clean` 的文件，`make clean` 仍然会执行清理命令。

## 10. Makefile 自动变量

| 变量 | 含义 | 示例结果 |
|---|---|---|
| `$@` | 当前规则的目标 | `user_app` |
| `$^` | 当前规则的全部依赖 | `main.o user.o` |
| `$<` | 第一个依赖 | `main.cpp` |

例如：

```makefile
user.o: user.cpp user.h
	$(CXX) $(CXXFLAGS) -c $< -o $@
```

等价于：

```makefile
user.o: user.cpp user.h
	$(CXX) $(CXXFLAGS) -c user.cpp -o user.o
```

## 11. 增量编译

Make 会比较目标文件和依赖文件的修改时间。

```text
目标不存在
或依赖比目标新
→ 执行命令
否则
→ 跳过命令
```

### 验证 1：连续执行

```bash
make
make
```

第二次应显示：

```text
make: Nothing to be done for 'all'.
```

### 验证 2：修改 `user.cpp`

修改 `user.cpp` 后执行：

```bash
make
```

预期只重新执行：

```text
user.o
user_app
```

不应重新编译 `main.o`。

### 验证 3：修改 `user.h`

执行：

```bash
touch user.h
make
```

因为 `main.o` 和 `user.o` 都依赖 `user.h`，所以两个都应重新编译，然后重新链接。

这就是 Makefile 的主要价值：

> 只重新编译真正受影响的文件，节省构建时间。

```bash

make clean    # 删除编译产物
make -n       # 只显示将执行的命令，不真正执行

```

## 13. 静态库和动态库

### 静态库

文件形式：

```text
libuser.a
```

创建：

```bash
ar rcs libuser.a user.o
```

链接：

```bash
g++ main.o -L. -luser -o user_app_static
```

特点：

- 链接时把需要的库代码装入可执行文件；
- 可执行文件通常更大；
- 运行时不再依赖 `libuser.a`。

### 动态库

文件形式：

```text
libuser.so
```

创建：

```bash
g++ -fPIC -c user.cpp -o user_pic.o
g++ -shared -o libuser.so user_pic.o
```

链接：

```bash
g++ main.o -L. -luser -o user_app_dynamic
```

运行时需要让系统找到动态库：

```bash
LD_LIBRARY_PATH=. ./user_app_dynamic
```

特点：

- 程序运行时加载动态库；
- 可执行文件通常更小；
- 部署时必须提供对应 `.so` 文件。

### 库相关参数

| 参数 | 含义 |
|---|---|
| `-I目录` | 添加头文件搜索目录 |
| `-L目录` | 添加库文件搜索目录 |
| `-l库名` | 链接指定库 |

例如：

```bash
-luser
```

会查找：

```text
libuser.a
libuser.so
```

## 14. 常见错误总表

| 错误 | 发生阶段 | 常见原因 |
|---|---|---|
| `user.h: No such file or directory` | 预处理/编译 | 头文件路径错误，缺少 `-I` |
| `undefined reference` | 链接 | 漏掉实现文件或库，函数签名不一致 |
| `multiple definition` | 链接 | 函数定义写进头文件并被多次包含 |
| `missing separator` | 读取 Makefile | 命令行前不是 Tab |
| `No rule to make target 'user.o'` | Make 构建 | 没有对应规则，或依赖文件缺失 |
| `cannot find -lxxx` | 链接 | 找不到指定库，检查 `-L` 和 `-l` |
| `error while loading shared libraries` | 运行时 | 动态库路径不正确 |

## 15. 与 TinyWebServer 的对应关系

TinyWebServer 的 `makefile`：

```makefile
CXX ?= g++
server: main.cpp webserver.cpp http/http_conn.cpp ...
	$(CXX) -o server $^ $(CXXFLAGS) -lpthread -lmysqlclient
```

对应关系：

| Day 4 知识 | TinyWebServer 中的体现 |
|---|---|
| `CXX` | 使用 `g++` 编译 |
| `CXXFLAGS` | 根据 DEBUG 添加 `-g` 或 `-O2` |
| 多个 `.cpp` | 服务器由多个模块共同构成 |
| `$^` | 展开为全部依赖源文件 |
| `-lpthread` | 链接 POSIX 线程库 |
| `-lmysqlclient` | 链接 MySQL 客户端库 |
| `server` | 最终可执行文件 |
| `clean` | 删除生成文件 |

今天看到 TinyWebServer 的 Makefile 时，应该能理解：

```text
它和 Day 4 的 Makefile 本质相同
只是源文件更多，并额外链接了线程库和 MySQL 库
```
