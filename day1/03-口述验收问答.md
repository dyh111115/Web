# Day 1 口述验收问答

> 用法：先遮住答案，用自己的话回答，再对照。  
> 目标不是背术语，而是能解释“为什么”。

## Q1. C++ 程序从哪里开始执行？

**答：** 从 `main()` 函数开始。操作系统启动程序后，会进入 `main()`。

## Q2. `main()` 的作用是什么？

**答：** `main()` 是程序入口，负责组织程序的主要流程。今天的 `main()` 只负责读取名字、生成问候语、输出结果，具体工作交给其他函数完成。

## Q3. 函数为什么需要参数和返回值？

**答：**

- 参数用于把数据传入函数；
- 返回值用于把结果交给调用者；
- 这样函数可以复用，职责更清楚，不必把所有逻辑都写在 `main()` 中。

例如：

```cpp
std::string buildGreeting(const std::string& name)
{
    return "Hello, " + name;
}
```

`name` 是参数，返回的字符串是返回值。

## Q4. `.h` 和 `.cpp` 文件分别放什么？

**答：**

- `.h` 放函数声明、类型声明和对外接口；
- `.cpp` 放函数的具体实现；
- `main.cpp` 是程序入口，负责调用这些函数。

可以理解为：

```text
.h   = 告诉编译器“有什么”
.cpp = 告诉编译器“怎么做”
```

## Q5. 为什么编译时要同时写 `main.cpp` 和 `greet.cpp`？

**答：** 因为两个文件都包含程序的一部分：

- `main.cpp` 调用函数；
- `greet.cpp` 提供函数实现。

编译器分别处理两个源文件，链接器再把它们组合起来。只编译 `main.cpp` 时，链接器找不到函数实现，就会报 `undefined reference`。

## Q6. `std::cin >> name` 和 `std::getline` 有什么区别？

**答：**

- `std::cin >> name` 读取一个“单词”，遇到空格或换行就停止；
- `std::getline(std::cin, name)` 读取一整行，可以保留空格。

输入：

```text
Alice Wang
```

前者通常得到 `Alice`，后者得到 `Alice Wang`。

## Q7. `undefined reference` 通常说明什么？

**答：** 说明编译阶段找到了函数声明，但链接阶段找不到函数实现。

例如执行：

```bash
g++ main.cpp -o greet
```

`main.cpp` 知道 `readName()` 的声明，但没有把 `greet.cpp` 中的实现链接进来，所以会报 `undefined reference`。

修复方式：

```bash
g++ main.cpp greet.cpp -o greet
```

## Q8. `const std::string&` 有什么好处？

**答：**

- `std::string` 表示参数类型是字符串；
- `&` 表示使用引用，不复制整个字符串；
- `const` 表示函数内部不能修改传入的内容。

所以它通常比直接传 `std::string` 更高效。

## Q9. 编译命令中的参数分别是什么意思？

```bash
g++ -std=c++17 -Wall -Wextra -pedantic main.cpp greet.cpp -o greet
```

**答：**

| 参数 | 含义 |
|---|---|
| `g++` | 调用 C++ 编译器 |
| `-std=c++17` | 使用 C++17 标准 |
| `-Wall` | 开启常见警告 |
| `-Wextra` | 开启更多警告 |
| `-pedantic` | 严格遵循标准 |
| `main.cpp greet.cpp` | 要编译和链接的源文件 |
| `-o greet` | 输出名为 `greet` 的可执行文件 |

## Q10. 为什么运行程序要写 `./greet`？

**答：** `./` 表示当前目录。写 `./greet` 是明确告诉系统：

> 运行当前目录下的 `greet` 文件。

如果只写 `greet`，系统会去 `PATH` 环境变量记录的目录中查找，而当前目录通常不在其中。

## Q11. 编译和链接有什么区别？

**答：**

- 编译：把 `.cpp` 源文件转成目标文件，主要检查语法和声明；
- 链接：把多个目标文件以及所需库组合起来，生成最终可执行文件。

简化流程：

```text
main.cpp + greet.cpp
→ 编译
→ main.o + greet.o
→ 链接
→ greet
```

## Q12. 头文件保护的作用是什么？

**答：**

```cpp
#ifndef GREET_H
#define GREET_H

// 声明

#endif
```

它防止同一个头文件被重复包含，从而避免重复声明或重复定义。

## Q13. 如何从 WSL 连接到 VS Code？

**答：** 先安装 VS Code 和 **WSL** 扩展，然后用下面任一方式连接：

- 点击 VS Code 左下角 `><`，选择 `Connect to WSL`；
- 或按 `Ctrl + Shift + P`，执行 `WSL: Connect to WSL`。

连接成功后，左下角会显示 `WSL: Ubuntu`。接着用 `File → Open Folder` 打开：

```text
/home/你的用户名/cpp-learning/week1/day01
```

连接后，VS Code 只是编辑器，编译和运行仍然在 WSL 的 Ubuntu 终端中完成。

## Q14. 如何确认 VS Code 的终端确实在 WSL 中？

**答：**

1. 按下面的组合键打开集成终端：

```text
Ctrl + `
```
2. 检查提示符是否类似：

```text
dyh@DESKTOP:/home/dyh/cpp-learning/week1/day01$
```

如果显示的是：

```text
PS C:\Users\dyh>
```

说明当前还是 PowerShell，需要重新执行：

```text
Ctrl + Shift + P → WSL: Connect to WSL
```

然后执行：

```bash
pwd
g++ --version
```

`pwd` 显示 `/home/...`，并且 `g++` 能显示版本，说明终端在 WSL 的 Ubuntu 环境中。
