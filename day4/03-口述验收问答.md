# Day 4 口述验收问答

> 用法：先遮住答案，用自己的话回答，再对照。  
> 目标：能解释编译、链接、Makefile 和多文件工程。

## Q1. 编译和链接有什么区别？

**答：**

- 编译：把单个 `.cpp` 源文件转换成 `.o` 目标文件，主要检查语法、类型和声明；
- 链接：把多个 `.o` 目标文件以及需要的库组合起来，解决函数实现和外部符号，生成最终可执行文件。

```text
main.cpp → main.o
user.cpp → user.o
main.o + user.o → user_app
```

## Q2. C++ 程序从源码到可执行文件大致经过哪些阶段？

**答：**

```text
预处理
→ 编译
→ 汇编
→ 链接
```

- 预处理：展开 `#include`，处理宏和条件编译；
- 编译：检查语法和类型，生成汇编代码；
- 汇编：生成 `.o` 目标文件；
- 链接：合并目标文件和库，生成可执行文件。

## Q3. `.h`、`.cpp`、`.o` 和可执行文件分别是什么？

**答：**

- `.h`：放类、函数和公共接口的声明；
- `.cpp`：放具体实现和程序入口；
- `.o`：单个 `.cpp` 编译后的目标文件；
- 可执行文件：链接完成后可以直接运行的程序。

一句话：

```text
.h 表示“有什么”
.cpp 表示“怎么做”
.o 是半成品
可执行文件是最终成品
```

## Q4. `main.cpp` 和 `user.cpp` 的接口是什么？

**答：** 两者通过 `user.h` 中的 `UserManager` 公共接口连接。

```cpp
UserManager();
bool addUser(const std::string&, const std::string&);
bool checkPassword(const std::string&, const std::string&) const;
void printAll() const;
```

调用过程：

```text
main.cpp 根据 user.h 检查调用是否合法
→ 链接器寻找 user.cpp 中的函数实现
→ 生成完整程序
```

`main.cpp` 不需要也不应该直接包含 `user.cpp`。

## Q5. 为什么头文件通常只放声明？

**答：** 因为头文件可能被多个 `.cpp` 包含。如果函数定义也放在头文件中，多个目标文件可能各自生成一份相同的定义，链接时出现：

```text
multiple definition
```

所以通常遵循：

```text
头文件：放声明
.cpp  ：放定义
```

## Q6. 头文件保护的作用是什么？

**答：**

```cpp
#ifndef USER_H
#define USER_H

// 声明

#endif
```

作用：防止同一个头文件在一次编译单元中被重复包含。

如果没有保护，重复包含可能导致类或声明被重复处理。

## Q7. `g++ -c` 有什么作用？

**答：** `-c` 表示只编译，不链接。

```bash
g++ -std=c++17 -Wall -Wextra -pedantic -c main.cpp -o main.o
```

这条命令只生成 `main.o`，不会生成可执行文件。

## Q8. 目标文件和可执行文件有什么区别？

**答：**

- `.o` 是单个源文件编译后的半成品，可能还有未解析的外部符号；
- 可执行文件已经完成链接，可以由操作系统加载运行。

可以使用下面命令查看：

```bash
file main.o
file user_app
```

通常 `main.o` 是 `relocatable`，`user_app` 是 `executable`。

## Q9. `undefined reference` 说明什么？

**答：** 说明编译阶段找到了函数声明，但链接阶段找不到函数实现。

例如：

```bash
g++ -std=c++17 main.cpp -o user_app
```

因为漏掉 `user.cpp`，会出现：

```text
undefined reference to `UserManager::addUser(...)'
```

修复：

```bash
g++ -std=c++17 main.cpp user.cpp -o user_app
```

## Q10. “头文件找不到”和“函数未定义”有什么区别？

**答：**

```text
头文件找不到 → 预处理/编译阶段错误
undefined reference → 链接阶段错误
```

- 头文件找不到：检查 `#include` 路径，可能需要 `-I`；
- 函数未定义：检查是否漏掉 `.cpp` 文件、库或函数签名是否一致。

## Q11. 两条错误命令分别有什么问题？

```bash
g++ main.cpp -o user_app
g++ main.cpp user.cpp -Iinclude -o user_app
```

**答：**

第一条只编译 `main.cpp`，没有提供 `user.cpp` 中的实现，因此会出现 `undefined reference`。

第二条中有 `-Iinclude`，但 `-I` 只用于头文件搜索，不会链接库。如果程序还依赖外部库，仍然需要正确的 `-L` 和 `-l` 参数。

## Q12. `nm` 看到的 `U` 和 `T` 是什么意思？

**答：**

- `U`：undefined，当前目标文件引用了一个尚未定义的符号；
- `T`：text，当前目标文件中有该函数的机器代码定义。

例如：

```text
main.o 中：U UserManager::addUser(...)
user.o 中：T UserManager::addUser(...)
```

链接器负责把 `U` 和对应的 `T` 连接起来。

## Q13. Makefile 的基本规则是什么？

**答：**

```makefile
目标: 依赖
	生成目标的命令
```

例子：

```makefile
user_app: main.o user.o
	$(CXX) $(CXXFLAGS) main.o user.o -o user_app
```

含义：

> 要生成 `user_app`，先准备 `main.o` 和 `user.o`，然后执行链接命令。

## Q14. Makefile 的命令行为什么必须用 Tab？

**答：** Make 使用 Tab 区分规则和命令。如果命令行前使用普通空格，可能报：

```text
missing separator
```

注意：不同编辑器可能把 Tab 自动转换成空格，写 Makefile 时要检查。

## Q15. `$@`、`$^`、`$<` 分别是什么？

**答：**

- `$@`：当前规则的目标；
- `$^`：当前规则的全部依赖；
- `$<`：第一个依赖。

例如：

```makefile
user.o: user.cpp user.h
	$(CXX) $(CXXFLAGS) -c $< -o $@
```

等价于：

```makefile
user.o: user.cpp user.h
	$(CXX) $(CXXFLAGS) -c user.cpp -o user.o
```

## Q16. Make 如何判断是否需要重新编译？

**答：** Make 比较目标文件和依赖文件的修改时间。

```text
目标不存在
或任一依赖比目标新
→ 执行命令
否则
→ 跳过命令
```

因此修改 `user.cpp` 后通常只重新生成 `user.o`，然后重新链接。

## Q17. 为什么修改 `user.h` 后要重新编译多个文件？

**答：** 因为 `main.o` 和 `user.o` 都依赖 `user.h`：

```makefile
main.o: main.cpp user.h
user.o: user.cpp user.h
```

头文件中的声明可能影响多个源文件，所以相关目标文件都需要重新编译。

## Q18. `clean` 和 `.PHONY` 有什么作用？

**答：**

```makefile
clean:
	rm -f $(TARGET) $(OBJS)

.PHONY: all clean
```

- `clean`：删除可执行文件和目标文件；
- `.PHONY`：声明 `all`、`clean` 是命令目标，不是实际文件。

即使目录中存在名为 `clean` 的文件，`make clean` 仍然会执行清理命令。

## Q19. `-I`、`-L`、`-l` 有什么区别？

**答：**

- `-I目录`：添加头文件搜索目录；
- `-L目录`：添加库文件搜索目录；
- `-l库名`：链接指定库。

例如：

```bash
g++ main.o -L. -luser -o user_app
```

表示在当前目录查找 `libuser.a` 或 `libuser.so`。

## Q20. 静态库和动态库有什么区别？

**答：**

- 静态库 `.a`：链接时把需要的代码装入可执行文件；
- 动态库 `.so`：程序运行时加载。

静态库通常让可执行文件更大，但运行时不再依赖 `.a`；动态库通常让可执行文件更小，但部署时必须提供 `.so`。

## Q21. TinyWebServer 的 Makefile 中有哪些知识已经在 Day 4 学过？

**答：** 例如：

```makefile
CXX ?= g++
server: main.cpp webserver.cpp ...
	$(CXX) -o server $^ $(CXXFLAGS) -lpthread -lmysqlclient
```

对应关系：

- `CXX`：指定编译器；
- `server`：最终目标；
- 多个 `.cpp`：多个模块的源文件；
- `$^`：全部依赖；
- `-lpthread`：链接线程库；
- `-lmysqlclient`：链接 MySQL 客户端库；
- `clean`：清理构建产物。

TinyWebServer 的源文件更多，但基本构建思想与今天的 Makefile 相同。
