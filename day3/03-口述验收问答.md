# Day 3 口述验收问答

> 用法：先遮住答案，用自己的话回答，再对照。  
> 目标：能解释三种容器、RAII 和文件描述符。

## Q1. `std::string`、`std::vector`、`std::map` 分别适合保存什么？

**答：**

- `std::string`：保存文本；
- `std::vector`：保存一组动态数据；
- `std::map`：保存“键 → 值”的对应关系。

## Q2. `vector` 和普通数组有什么区别？

**答：**

- 普通数组大小固定；
- `vector` 可以动态增加和删除元素；
- `vector` 自动管理内部内存；
- `vector` 可以用 `size()` 获取当前元素数量。

## Q3. 为什么 `map` 适合保存用户名和密码？

**答：** 因为用户名是唯一的键，密码是对应的值。

```cpp
std::map<std::string, std::string> users;
users["admin"] = "123456";
```

通过用户名可以快速找到对应密码。

## Q4. `users["unknown"]` 和 `users.find("unknown")` 有什么区别？

**答：**

- `users["unknown"]` 如果键不存在，会自动插入一个空值；
- `users.find("unknown")` 只查找，不会插入新元素；
- 所以查询用户时应优先使用 `find()`。

## Q5. `map::find()` 返回什么？

**答：** 返回一个迭代器。

- 找到时，迭代器指向对应元素；
- 没找到时，等于 `users.end()`。

```cpp
auto it = users.find(name);

if (it != users.end())
{
    std::cout << it->first << '\n';
    std::cout << it->second << '\n';
}
```

## Q6. 什么是 RAII？

**答：** RAII 是把资源的生命周期绑定到对象生命周期上。

```text
构造函数：获取资源
对象使用期间：资源有效
析构函数：释放资源
```

## Q7. 为什么析构函数适合释放资源？

**答：** 因为对象离开作用域或销毁时，析构函数会自动执行，不需要在每条返回路径上手动释放资源。

## Q8. `FdGuard` 的构造函数和析构函数分别做什么？

**答：**

- 构造函数：调用 `open()` 打开文件，把 fd 保存到 `fd_`；
- 析构函数：如果 fd 有效，调用 `close()` 关闭资源。

## Q9. 什么是文件描述符 fd？

**答：** fd 是操作系统分配给打开资源的编号，不是文件本身。

```text
0：标准输入
1：标准输出
2：标准错误
3、4、5……：文件、Socket、管道等
```

可以使用 fd 进行读取、写入和关闭操作。

## Q10. `open(path.c_str(), O_RDONLY)` 是什么？

**答：** 这是 Linux 的 `open()` 系统调用。

- `path.c_str()`：把 `std::string` 转成 C 风格字符串；
- `O_RDONLY`：以只读方式打开；
- 成功返回非负 fd；
- 失败返回 `-1`。

## Q11. `close(fd)` 做了什么？

**答：** `close()` 告诉操作系统该 fd 对应的资源不再使用，可以回收。

关闭后：

- 不能再继续使用原来的 fd；
- 编号之后可能被新的文件或 Socket 重复使用。

## Q12. fd 会被销毁吗？

**答：** 要区分两件事：

- `fd_` 是一个整数变量，对象销毁时它也随之消失；
- fd 对应的系统资源由 `close()` 释放。

所以真正关闭资源的是 `close(fd_)`，不是整数变量本身消失。

## Q13. 如果忘记 `close()` 会怎样？

**答：** 文件描述符会一直占用，可能造成 fd 泄漏。打开的文件或 Socket 越来越多后，可能达到进程上限。

进程退出时 Linux 会清理仍然打开的资源，但长期运行的服务器不能依赖进程退出。

## Q14. `std::string`、`std::vector`、`std::map` 为什么也算 RAII 类型？

**答：** 它们在内部管理动态内存，对象销毁时会自动释放这些内存，不需要用户手动 `delete`。

## Q15. TinyWebServer 的 `connectionRAII` 可能负责什么？

**答：**

- 构造时从数据库连接池获取连接；
- 析构时自动把连接归还连接池。

它和 `FdGuard` 一样，都是通过对象生命周期管理资源。

## Q16. 为什么 Web 服务器中经常提到 fd？

**答：** 因为文件、监听 Socket、客户端 Socket、epoll 实例在 Linux 中都可以用 fd 表示。

后续会看到：

```cpp
int listenfd;
int connfd;
int epollfd;
```

服务器通过 fd 接收连接、读写数据，并在结束时关闭 fd。
