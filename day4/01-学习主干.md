## 4. 七个核心结论

1. **`.h` 放声明，`.cpp` 放实现。**
2. **`main.cpp` 通过 `user.h` 使用 `user.cpp` 中的功能。**
3. **编译把单个 `.cpp` 变成 `.o`，链接把多个 `.o` 和库变成可执行文件。**
4. **`undefined reference` 通常表示链接时找不到函数实现。**
5. **Makefile 描述目标、依赖和生成目标的命令。**
6. **Makefile 的命令行必须以 Tab 开头。**
7. **`make` 根据文件修改时间，只重新执行受影响的部分。**

需要特别理解：

```text

链接器负责把调用和实现连接到一起
```

## 6. 接口关系

`user.h` 中的公共接口：

```cpp
class UserManager
{
public:
    UserManager();

    bool addUser(const std::string& name,
                 const std::string& password);

    bool checkPassword(const std::string& name,
                       const std::string& password) const;

    void printAll() const;

private:
    std::map<std::string, std::string> users_;
};
```

调用关系：

```text
main.cpp 调用 users.addUser(...)
→ 编译器根据 user.h 检查参数和返回值
→ 链接器寻找 user.cpp 中的 UserManager::addUser(...) 实现
→ 生成完整可执行程序
```

## 7. 编译与链接

### 一次性编译

```bash
g++ -std=c++17 -Wall -Wextra -pedantic main.cpp user.cpp -o user_app
```

### 分步编译

```bash
g++ -std=c++17 -Wall -Wextra -pedantic -c main.cpp -o main.o
g++ -std=c++17 -Wall -Wextra -pedantic -c user.cpp -o user.o
g++ main.o user.o -o user_app
```

### 使用 Makefile

```bash
make
./user_app
```

### 清理

```bash
make clean
```

完整关系：

```text
main.cpp ──编译──> main.o ─┐
                           ├──链接──> user_app
user.cpp ──编译──> user.o ─┘
```

## 8. Makefile 的核心规则

```makefile
目标: 依赖
	生成目标的命令
```

示例：

```makefile
user_app: main.o user.o
	$(CXX) $(CXXFLAGS) main.o user.o -o user_app
```

Make 的判断过程：

```text
目标不存在
或任一依赖比目标更新
→ 执行命令
否则
→ 不重复构建
```

## 10. 和 TinyWebServer 的关系

TinyWebServer 的 `makefile` 使用同样的工程化思路：

```makefile
CXX ?= g++
server: main.cpp webserver.cpp http/http_conn.cpp ...
	$(CXX) -o server $^ $(CXXFLAGS) -lpthread -lmysqlclient
```

| Day 4 知识 | TinyWebServer 中的体现 |
|---|---|
| `CXX` | 指定 C++ 编译器 |
| 多个 `.cpp` | 服务器由多个模块组成 |
| 最终目标 | 生成 `server` 可执行文件 |
| `$^` | 展开为全部依赖文件 |
| `-lpthread` | 链接线程库 |
| `-lmysqlclient` | 链接 MySQL 客户端库 |
| `clean` | 删除生成的可执行文件 |

今天只需掌握基本编译和 Makefile，不要求理解全部模块依赖。
