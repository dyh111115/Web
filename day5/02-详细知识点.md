# Day 5 详细知识点

## 1. 文件描述符 fd

文件描述符的英文是：

```text
File Descriptor
```

简称：

```text
fd
```

定义：

> fd 是 Linux 内核分配给进程的资源编号，用于访问已经打开的资源。

fd 不是文件本身，而是访问资源的句柄。可以类比为：

```text
资源：图书馆中的书
fd：借书证上的编号
```

Linux 中很多对象都统一通过 fd 访问：

```text
普通文件
目录
标准输入输出
管道
Socket
epoll 实例
```

因此 Web 服务器中经常出现：

```cpp
int listenfd;  // 监听 Socket
int connfd;    // 客户端连接 Socket
int epollfd;   // epoll 实例
```

它们的类型都是 `int`，本质都是 fd。

## 2. 三个标准文件描述符

每个进程启动时通常已经打开三个标准 fd：

| fd | 名称 | 默认用途 |
|---|---|---|
| `0` | 标准输入 `stdin` | 键盘或终端输入 |
| `1` | 标准输出 `stdout` | 正常输出 |
| `2` | 标准错误 `stderr` | 错误输出 |

之后打开的新文件通常从 `3` 开始分配，但具体编号由操作系统决定。

新 fd 一般使用当前最小的可用编号。因此：

```text
0、1、2 已占用
→ open() 通常返回 3
```

关闭 fd 后，这个编号之后可能被新的资源复用。

## 3. `open()`、`read()`、`write()`、`close()`

### `open()`

```cpp
int fd = open(path.c_str(), O_RDONLY);
```

- `open()` 是 Linux 系统调用；
- `path.c_str()` 把 `std::string` 转成 C 风格字符串；
- 成功返回非负 fd；
- 失败返回 `-1`。

常见打开标志：

| 标志 | 含义 |
|---|---|
| `O_RDONLY` | 只读 |
| `O_WRONLY` | 只写 |
| `O_RDWR` | 读写 |
| `O_CREAT` | 文件不存在时创建 |
| `O_TRUNC` | 清空已有内容 |

### `read()`

```cpp
char buffer[1024];
ssize_t n = read(fd, buffer, sizeof(buffer));
```

返回值：

```text
n > 0   读取到 n 个字节
n == 0  到达文件末尾 EOF，或 Socket 对端关闭
n == -1 读取失败
```

`read()` 只会写入读到的字节，不会自动添加字符串结束符。因此要输出文本时需要：

```cpp
buffer[n] = '\0';
```

### `write()`

```cpp
ssize_t n = write(fd, data, length);
```

返回值通常表示实际写入了多少字节。不能假设一次 `write()` 一定会写完所有数据，这个问题在后续 Socket 编程中会再次出现。

### `close()`

```cpp
close(fd);
```

`close()` 的作用：

> 告诉操作系统当前进程不再使用这个 fd 对应的资源。

关闭后：

- 原 fd 不能继续使用；
- fd 编号之后可能被其他 `open()` 或 `socket()` 复用；
- 长期运行的程序必须正确关闭 fd，避免 fd 泄漏。

## 4. 使用 `/proc` 查看 fd

Linux 的 `/proc` 是内核提供的虚拟文件系统。

查看当前 shell 的 fd：

```bash
ls -l /proc/$$/fd
```

`$$` 表示当前 shell 的 PID。

可能输出：

```text
0 -> /dev/pts/0
1 -> /dev/pts/0
2 -> /dev/pts/0
```

打开 fd 3：

```bash
exec 3< /etc/passwd
ls -l /proc/$$/fd
```

可以看到：

```text
3 -> /etc/passwd
```

读取一行：

```bash
read -u 3 first_line
printf '%s\n' "$first_line"
```

关闭 fd 3：

```bash
exec 3<&-
```

再次查看：

```bash
ls -l /proc/$$/fd
```

fd 3 已经消失。

## 5. 完整示例：`fd_demo.cpp`

```cpp
#include <fcntl.h>
#include <unistd.h>

#include <iostream>

int main()
{
    std::cout << "当前进程 PID: " << getpid() << '\n';

    int fd = open("/etc/passwd", O_RDONLY);

    if (fd == -1)
    {
        std::cerr << "open failed\n";
        return 1;
    }

    std::cout << "打开文件后 fd = " << fd << '\n';

    char buffer[128];
    ssize_t n = read(fd, buffer, sizeof(buffer) - 1);

    if (n > 0)
    {
        buffer[n] = '\0';
        std::cout << "读取内容:\n" << buffer << '\n';
    }
    else if (n == 0)
    {
        std::cout << "文件为空或已到末尾\n";
    }
    else
    {
        std::cerr << "read failed\n";
    }

    close(fd);
    std::cout << "文件已关闭\n";

    return 0;
}
```

流程：

```text
getpid() 获取 PID
→ open() 打开文件
→ read() 读取最多 127 个字节
→ 手动添加 '\0'
→ close() 关闭 fd
```

`sizeof(buffer) - 1` 是为了给字符串结束符预留一个字节。

## 6. 程序和进程

| 概念 | 含义 |
|---|---|
| 程序 | 磁盘上的可执行文件 |
| 进程 | 正在运行的程序实例 |

例如：

```text
user_app 是程序
./user_app 运行后产生一个进程
```

每个进程拥有：

```text
PID       进程 ID
PPID      父进程 ID
虚拟地址空间
文件描述符表
寄存器状态
程序计数器
```

可以使用：

```bash
ps
top
```

查看系统中的进程。

获取当前进程和父进程 ID：

```cpp
getpid();
getppid();
```

## 7. 进程之间内存独立

进程拥有独立的虚拟地址空间。

因此：

```text
进程 A 的全局变量
和进程 B 的全局变量
不是同一份内存
```

即使两个进程运行同一个可执行文件，它们的全局变量也互不影响。

进程间通信需要使用：

```text
管道
Socket
共享内存
消息队列
文件
```

## 8. `fork()` 创建子进程

```cpp
pid_t pid = fork();
```

返回值：

```text
pid > 0  父进程中，返回值是子进程 PID
pid == 0 子进程中
pid == -1 创建失败
```

调用 `fork()` 后，父子进程都会从 `fork()` 后面的代码继续执行。

因此程序通常根据返回值区分父进程和子进程：

```cpp
if (pid == 0)
{
    // 子进程
}
else
{
    // 父进程
}
```

## 9. 完整示例：`fork_demo.cpp`

```cpp
#include <sys/wait.h>
#include <unistd.h>

#include <iostream>

int main()
{
    int value = 100;

    pid_t pid = fork();

    if (pid == -1)
    {
        std::cerr << "fork failed\n";
        return 1;
    }

    if (pid == 0)
    {
        value = 200;
        std::cout << "子进程: pid=" << getpid()
                  << ", ppid=" << getppid()
                  << ", value=" << value << std::endl;
        _exit(0);
    }

    int status = 0;
    waitpid(pid, &status, 0);

    std::cout << "父进程: pid=" << getpid()
              << ", child pid=" << pid
              << ", value=" << value << std::endl;

    return 0;
}
```

可能输出：

```text
子进程: pid=12346, ppid=12345, value=200
父进程: pid=12345, child pid=12346, value=100
```

关键结论：

```text
子进程把 value 改成 200
父进程的 value 仍然是 100
```

这说明父子进程拥有相互独立的地址空间。

### 写时复制

Linux 通常不会在 `fork()` 时立刻复制父进程的全部内存，而是采用写时复制：

```text
fork() 后先共享只读页面
某个进程写入时
→ 再复制对应页面
```

逻辑效果仍然是：

> 父子进程的内存修改互不影响。

### `waitpid()`

```cpp
waitpid(pid, &status, 0);
```

作用：

> 父进程等待指定子进程结束，并回收子进程的退出状态。

如果不回收已经结束的子进程，可能产生僵尸进程。

## 10. 线程

线程是进程内部的执行流。

一个进程可以有多个线程：

```text
进程
├── 主线程
├── 工作线程 1
├── 工作线程 2
└── 工作线程 3
```

线程之间共享：

```text
代码段
全局变量
堆内存
打开的文件和 fd
```

每个线程独有：

```text
栈
寄存器
程序计数器
线程局部数据
```

线程共享同一个地址空间，所以一个线程修改全局变量后，另一个线程可以看到修改结果。

## 11. C++ 创建线程

使用标准线程库：

```cpp
#include <thread>

std::thread t(worker);
```

等待线程结束：

```cpp
t.join();
```

`join()` 表示：

> 当前线程阻塞，直到目标线程执行结束。

线程对象销毁前必须处理：

```cpp
t.join();    // 等待线程结束
```

或：

```cpp
t.detach();  // 分离线程
```

如果既不 `join()` 也不 `detach()`，`std::thread` 析构时会调用 `std::terminate()`。

编译线程程序需要 `-pthread`：

```bash
g++ -std=c++17 -Wall -Wextra -pedantic -pthread thread_demo.cpp -o thread_demo
```

## 12. 数据竞争

考虑：

```cpp
int counter = 0;
++counter;
```

概念上可以拆成：

```text
读取 counter
加 1
写回 counter
```

两个线程可能交替执行：

```text
线程 A 读到 10
线程 B 读到 10
线程 A 写回 11
线程 B 写回 11
```

本来应增加两次，结果只增加了一次。

这称为：

```text
数据竞争
Data Race
```

数据竞争会导致结果错误，并属于未定义行为。

## 13. `std::mutex`

互斥锁用来保护临界区：

```cpp
std::mutex counter_mutex;
```

手动加锁和解锁：

```cpp
counter_mutex.lock();
++counter;
counter_mutex.unlock();
```

这种方式容易因为提前返回或异常导致忘记解锁。

## 14. `std::lock_guard`

推荐使用 RAII 风格：

```cpp
{
    std::lock_guard<std::mutex> lock(counter_mutex);
    ++counter;
}
```

执行过程：

```text
构造 lock_guard
→ 自动加锁

离开作用域
→ 自动解锁
```

与 Day 3 的 RAII 思想一致：

```text
构造函数获取资源
析构函数释放资源
```

这里获取和释放的资源是互斥锁。

## 15. 完整示例：`thread_demo.cpp`

```cpp
#include <iostream>
#include <mutex>
#include <thread>

int counter = 0;
std::mutex counter_mutex;

void add(int times)
{
    for (int i = 0; i < times; ++i)
    {
        std::lock_guard<std::mutex> lock(counter_mutex);
        ++counter;
    }
}

int main()
{
    std::thread t1(add, 500000);
    std::thread t2(add, 500000);

    t1.join();
    t2.join();

    std::cout << "counter = " << counter << '\n';

    return 0;
}
```

预期输出：

```text
counter = 1000000
```

两个线程都能访问全局变量 `counter`，因为它们属于同一个进程。

`counter_mutex` 保证同一时刻只有一个线程能执行：

```cpp
++counter;
```

## 16. 不加锁会怎样

错误示例：

```cpp
void addUnsafe(int times)
{
    for (int i = 0; i < times; ++i)
    {
        ++counter;
    }
}
```

如果两个线程同时执行 `addUnsafe()`，最终结果可能小于 `1000000`，并且每次运行结果可能不同。

不要使用“多运行几次看起来正确”来判断并发程序是否正确。数据竞争本身就是错误。

C++ 还提供了 `std::atomic<int>` 用于简单原子计数，但今天先掌握 mutex，因为它能保护更复杂的临界区。

## 17. 进程和线程对比

| 对比项 | 进程 | 线程 |
|---|---|---|
| 地址空间 | 独立 | 共享所属进程 |
| 全局变量 | 不共享 | 共享 |
| 堆内存 | 不共享 | 共享 |
| fd | 独立 fd 表 | 同一进程内共享 |
| 栈 | 独立 | 每个线程独立 |
| 寄存器 | 独立 | 每个线程独立 |
| 创建开销 | 较大 | 较小 |
| 通信方式 | 管道、Socket、共享内存 | 直接访问共享变量 |
| 隔离性 | 较强 | 较弱 |
| 同步需求 | 进程间通信需要同步 | 共享数据需要同步 |

一句话记忆：

```text
进程：资源隔离
线程：资源共享，调度更轻量
```

## 18. 主线程和工作线程

主线程：

```cpp
int main()
{
    // 主线程
}
```

创建工作线程：

```cpp
std::thread worker(task);
worker.join();
```

Web 服务器中的简化模型：

```text
主线程
→ epoll_wait()
→ accept() 得到 connfd
→ 把任务交给工作线程

工作线程
→ 读取 HTTP 请求
→ 解析请求
→ 生成响应
→ 发送响应
```

多个线程可能访问：

```text
任务队列
连接状态
连接池
日志对象
共享计数器
```

这些结构需要互斥锁、条件变量或其他同步机制保护。

## 19. Makefile

Day 5 可以使用下面的 Makefile：

```makefile
CXX ?= g++
CXXFLAGS ?= -std=c++17 -Wall -Wextra -pedantic

.PHONY: all clean

all: fd_demo fork_demo thread_demo

fd_demo: fd_demo.cpp
	$(CXX) $(CXXFLAGS) $< -o $@

fork_demo: fork_demo.cpp
	$(CXX) $(CXXFLAGS) $< -o $@

thread_demo: thread_demo.cpp
	$(CXX) $(CXXFLAGS) -pthread $< -o $@

clean:
	rm -f fd_demo fork_demo thread_demo
```

其中 `	` 在实际文件中是 Tab。

命令：

```bash
make          # 构建三个程序
./fd_demo
./fork_demo
./thread_demo
make clean    # 删除三个可执行文件
```

## 20. 常见错误

| 错误 | 原因 | 处理 |
|---|---|---|
| `open failed` | 文件不存在或无权限 | 检查路径和权限 |
| `read failed` | fd 无效或读取失败 | 检查 `open()` 返回值 |
| 读取内容末尾出现乱码 | 没有添加 `'\0'` | 执行 `buffer[n] = '\0'` |
| 父进程看不到子进程修改 | 父子进程内存独立 | 使用进程间通信 |
| `std::thread` 未定义 | 没包含 `<thread>` | 加 `#include <thread>` |
| 链接线程相关符号失败 | 编译时缺少 `-pthread` | 加 `-pthread` |
| `terminate called without an active exception` | 线程对象销毁前没有 `join()` 或 `detach()` | 调用 `join()` |
| `counter` 结果不正确 | 多线程修改共享数据没有同步 | 使用 mutex |
| Makefile `missing separator` | 命令行不是 Tab | 改成 Tab |

## 21. 与 TinyWebServer 的对应关系

TinyWebServer 中：

```cpp
int listenfd;
int connfd;
int epollfd;
```

分别表示：

```text
监听 Socket
客户端连接 Socket
epoll 实例
```

它们都是 fd。

TinyWebServer 的线程池会创建工作线程：

```cpp
pthread_create(...)
pthread_join(...)
```

主线程负责事件循环，工作线程处理连接任务。

共享数据结构需要同步，例如：

```text
任务队列
数据库连接池
日志
连接状态
```

因此会看到锁、条件变量等机制。

后续学习 `EPOLLONESHOT` 时还会解决：

> 同一个连接的事件可能被多个工作线程同时处理的问题。

今天只需掌握基本进程和线程模型，不要求实现线程池。
